# 8-5967: Detected a mixed tristate reset assignment

**Message:** `[Synth 8-5967] Detected a mixed tristate reset assignment for register r_fpga_io_reg`
**Severity:** CRITICAL WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A register's reset path assigns a mix of a tristate (`'Z'`) value and a normal
logic value. A flip-flop reset cannot drive high-impedance, so this mixed
tristate/reset description cannot map to a single register and may synthesize
incorrectly.

---

## Common Patterns

### P1: Tristate value on a register reset

**Problematic Code:**
```diff
-- Detected a mixed tristate reset assignment for register r_fpga_io_reg
```

**Recommended Fix:**
```vhdl
-- Drive the FF with 0/1 only; model 'Z' with an explicit output buffer
process(clk) begin
  if rising_edge(clk) then q <= d; end if;   -- register never drives 'Z'
end process;
io_pad <= q when oe = '1' else 'Z';          -- tri-state at the pad only
```

---

## Fix Strategy

1. Never drive a flip-flop's reset path with `'Z'` — registers can only be `0`/`1`; model high-impedance with an explicit output tri-state buffer at the pad.
2. Split the description: a clocked process drives the register with `0`/`1`, and a separate concurrent assignment applies the tri-state (`pad <= q when oe else 'Z';`).
3. Ensure the reset value is a defined logic level, not a mix of `Z` and logic.
4. Treat this CRITICAL WARNING as a functional risk and verify the tri-state/reset behavior post-synthesis.
