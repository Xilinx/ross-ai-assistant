# 8-4675: Function Name Not Uninstantiated

**Message:** `[Synth 8-4675] a function name may not be an uninstantiated subprogram`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A VHDL function name references something that is not an uninstantiated subprogram.

---

## Common Patterns

### P1: Instantiating a non-generic subprogram

**Problematic Code:**
```diff
-- Before: trying to use non-generic function as generic
function my_func is new some_func generic map(...);  -- ERROR: some_func not generic
```

**Recommended Fix:**
```diff
-- After: ensure source is a generic (uninstantiated) subprogram
-- Check that the function being instantiated is declared with 'generic'
```

---

## Fix Strategy

1. Only **uninstantiated (generic) subprograms** can be instantiated with `is new ... generic map(...)` — ensure the source subprogram is declared as a generic subprogram.
2. If the source is an ordinary function/procedure, either make it a generic subprogram or call it directly instead of instantiating it.
3. Verify the name resolves to a subprogram (not a signal/type) and is visible in scope.
4. Note that VHDL-2008 generic subprograms/packages may not be supported by all synthesis flows — confirm tool support or refactor to plain subprograms.
