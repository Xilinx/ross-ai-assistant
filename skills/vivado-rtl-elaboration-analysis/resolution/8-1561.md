# 8-1561: Ref Types Must Be Equivalent

**Message:** `[Synth 8-1561] actual and formal for a ref must be equivalent types`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A SystemVerilog `ref` port's actual and formal types must be equivalent (identical types).

---

## Common Patterns

### P1: Non-equivalent types on a ref port

**Problematic Code:**
```diff
// Before: non-equivalent ref types
module m(ref int in1);
m inst(.in1(logic_val));  // ERROR: logic != int
```

**Recommended Fix:**
```diff
// After: match types exactly
int int_val;
m inst(.in1(int_val));  // types match
// Note: ref ports are not synthesizable
```

---

## Fix Strategy

1. For a `ref` port, the actual and formal must be the **identical** type — declare the connected object with exactly the port's type (e.g., both `int`).
2. For synthesizable RTL, avoid `ref` ports entirely; use ordinary `input`/`output` ports with matching packed types.
3. If `ref` is used for a large struct/array in verification code, ensure a single shared `typedef` from a package is used on both sides.
4. Do not rely on implicit conversion across a `ref` connection — it is not permitted.
