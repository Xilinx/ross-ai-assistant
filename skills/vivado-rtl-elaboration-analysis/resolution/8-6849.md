# 8-6849: Infeasible attribute ram_style = "block" set

**Message:** `[Synth 8-6849] Infeasible attribute ram_style = "block" set for RAM "top/v_bram_tdp_be_arw_rf_brw_nc_01_03_inst/RAM_reg",trying to implement using LUTRAM`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A `ram_style = "block"` attribute cannot be honored for this RAM (too small, or a
shape/access pattern that does not fit a Block RAM), so Vivado falls back to
LUTRAM/distributed RAM.

---

## Common Patterns

### P1: ram_style=block infeasible

**Problematic Code:**
```diff
-- Infeasible attribute ram_style = "block" set for RAM "top/v_bram_tdp_be_arw_rf_brw_nc_01_03_inst/RAM_reg",trying to implement using LUTRAM
```

**Recommended Fix:**
```verilog
// Either accept LUTRAM for small memories, or make BRAM feasible
// (larger depth + synchronous read), or drop the block attribute:
(* ram_style = "distributed" *) reg [7:0] RAM [0:15];   // small -> LUTRAM
```

---

## Fix Strategy

1. If the memory is small, accept LUTRAM — `ram_style = "block"` cannot be honored, so either drop the attribute or set `ram_style = "distributed"` explicitly.
2. To actually get BRAM, make the memory BRAM-feasible: increase depth/width, use a synchronous (registered) read, and match the supported template.
3. Check for a shape/access pattern (asynchronous read, tiny depth) that prevents BRAM mapping and fix it.
4. Verify the resulting implementation in the synthesis report meets your resource/timing goals.
