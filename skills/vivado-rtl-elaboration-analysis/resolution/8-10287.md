# 8-10287: Mixed ANSI and Non-ANSI Port Styles

**Message:** `[Synth 8-10287] function with an ANSI port header should not have a non-ANSI style port declaration`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Vivado Message

```
ERROR: [Synth 8-10287] function with an ANSI port header should not have a non-ANSI style port declaration [/path/to/file:NN]
```

---

## Root Cause

A SystemVerilog function/task uses ANSI-style ports in the header but also has non-ANSI port declarations in the body.

---

## Common Patterns

### P1: Mixed ANSI/non-ANSI function ports

**Problematic Code:**
```diff
// Before: mixed ANSI and non-ANSI ports
function shortint func2();       // ANSI header (empty)
  input bit[4:0] in1 = 11;      // ERROR: non-ANSI declaration
  input bit[4:0] in2;
  begin
    func2 = {~(in1), {2{in2}}, ~in2};
  end
endfunction
```

**Recommended Fix:**
```diff
// After: use consistent ANSI style
function shortint func2(input bit[4:0] in1 = 11, input bit[4:0] in2);
  begin
    func2 = {~(in1), {2{in2}}, ~in2};
  end
endfunction
```

---

## Fix Strategy

1. Use one port style consistently for the function/task — move all port declarations into the ANSI header (`function shortint func2(input bit[4:0] in1 = 11, input bit[4:0] in2);`).
2. Do not mix an ANSI header with body `input`/`output` declarations for the same subprogram.
3. If you prefer non-ANSI, leave the header port list bare and declare directions in the body.
4. Verify default values move with their ports into the header.
