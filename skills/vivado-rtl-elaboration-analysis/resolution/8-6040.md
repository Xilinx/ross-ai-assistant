# 8-6040: Register attenuation_reg driving address of a

**Message:** `[Synth 8-6040] Register attenuation_reg driving address of a ROM cannot be packed in BRAM/URAM because of presence of initial value.`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A register that drives a ROM's address has an **initial value**. BRAM/URAM
address registers cannot carry an initial value, so the address register cannot
be packed into the block, hurting timing and utilization.

---

## Common Patterns

### P1: ROM address register with initial value

**Problematic Code:**
```diff
-- Register attenuation_reg driving address of a ROM cannot be packed in BRAM/URAM because of presence of initial value.
```

**Recommended Fix:**
```verilog
// Remove the initial value on the ROM address register; reset it synchronously
always @(posedge clk)
  if (rst) attenuation_reg <= '0;   // no 'initial' value -> packs into BRAM/URAM
  else     attenuation_reg <= next_addr;
```

---

## Fix Strategy

1. Remove the **initial value** on the register that drives the ROM address — BRAM/URAM address registers cannot carry one, which blocks packing into the block.
2. Establish the needed start value via a synchronous reset in the clocked process instead of an initializer.
3. Verify the ROM read still produces the intended first-address behavior after moving to reset-based initialization.
4. Re-check the synthesis report to confirm the address register now packs into BRAM/URAM.
