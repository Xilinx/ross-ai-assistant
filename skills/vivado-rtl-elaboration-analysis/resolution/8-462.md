# 8-462: No Clock in Event Control

**Message:** `[Synth 8-462] no clock signal specified in event control`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

An always block's event control has no recognizable clock signal.

---

## Common Patterns

### P1: Level-sensitive list used for flip-flop logic

**Problematic Code:**
```diff
// Before: no clock edge
always @(data or enable)  // level-sensitive — Vivado may expect clock
  q <= d;  // looks like flip-flop but no clock
```

**Recommended Fix:**
```diff
// After: add clock for sequential logic
always @(posedge clk)
  if (enable) q <= d;
// Or use combinational:
always @(*)
  q = d & enable;
```

---

## Fix Strategy

1. Decide whether the block is sequential or combinational, then give it the right event control:
   - **Sequential (flip-flop):** `always @(posedge clk)` (add `or negedge rst_n` for async reset) and use non-blocking `<=`.
   - **Combinational:** `always @(*)` (or `always_comb`) and use blocking `=`.
2. Do not use a level-sensitive list (`@(a or b)`) with non-blocking `<=` — that looks like a flip-flop with no clock and triggers this error.
3. If a clock exists but was not recognized, ensure it appears as a proper `posedge`/`negedge` edge in the sensitivity list.
4. Prefer `always_ff`/`always_comb` so the tool enforces correct event control and flags accidental latches.
