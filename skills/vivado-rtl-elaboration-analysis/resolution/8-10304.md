# 8-10304: Signal Declaration in Wrong Scope

**Message:** `[Synth 8-10304] signal declaration is not allowed in a package, subprogram, process statement, or protected type body`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Vivado Message

```
ERROR: [Synth 8-10304] signal declaration is not allowed in a package, subprogram, process statement, or protected type body [/path/to/file:NN]
```

---

## Root Cause

A VHDL signal is declared inside a process, subprogram, or package where signals are not allowed.

---

## Common Patterns

### P1: Signal declared in an illegal scope

**Problematic Code:**
```diff
-- Before: signal inside process (illegal)
process(sel)
  package varPack is
    signal sig1 : integer;  -- ERROR: not allowed here
  end package;
begin
  ...
end process;
```

**Recommended Fix:**
```diff
-- After: declare signal in architecture
architecture rtl of top is
  signal sig1 : integer;  -- moved to architecture declarative region
begin
  process(sel)
  begin
    sig1 <= ...;
  end process;
end;
```

---

## Fix Strategy

1. Declare signals in the **architecture** declarative region (before `begin`), not inside a process, subprogram, package, or protected-type body.
2. Inside a process/subprogram, use `variable`s for local storage instead of signals.
3. For shared state across processes, use an architecture-level signal driven by well-defined logic.
4. Move the offending declaration up to the architecture and reference it from the process.
