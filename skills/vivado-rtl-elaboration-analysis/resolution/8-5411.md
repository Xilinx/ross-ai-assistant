# 8-5411: Primitive module \oproc/scaler/scaler_component_

**Message:** `[Synth 8-5411] Primitive module \oproc/scaler/scaler_component_`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

Vivado reports that a referenced module is being treated as an unelaborated
**primitive/black box** — its RTL definition was not found, so synthesis keeps it
as an opaque instance. This usually means the source file/IP that defines the
module is missing from the fileset, is misnamed, or is a technology primitive
that is expected to remain a leaf cell.

---

## Common Patterns

### P1: Module treated as a primitive because its RTL is missing

**Problematic Code:**
```systemverilog
// scaler_component's RTL was never added to the project
scaler_component u_scaler (.clk(clk), .din(din), .dout(dout));
```

**Fix - add/compile the module's source (or its IP) to the fileset:**
```tcl
add_files scaler_component.v      # provide the missing RTL
# or generate/upgrade the IP that implements scaler_component
```

### P2: Intentional primitive / library cell

**Fix - if it is meant to be a leaf primitive, provide a proper black-box stub:**
```systemverilog
(* black_box *)
module scaler_component(input clk, input [7:0] din, output [7:0] dout);
endmodule
```

---

## Fix Strategy

1. Determine whether the reported module should have RTL — if so, add/compile its source file or generate the IP so Vivado elaborates it instead of leaving it a primitive.
2. Fix any name/case mismatch between the instance's module name and the actual definition.
3. If the module is intentionally a leaf cell, declare a proper `(* black_box *)` stub with the full, correctly-sized port list so downstream checks work.
4. Confirm the instance's connections match the (real or stubbed) port definition after resolving it.
