# 8-10438: Conflicting UDP Table Entry

**Message:** `[Synth 8-10438] UDP table entry conflicts with a previous entry`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Vivado Message

```
ERROR: [Synth 8-10438] UDP table entry conflicts with a previous entry [/path/to/file:NN]
```

---

## Root Cause

A UDP (User-Defined Primitive) has two table entries with the same input pattern but different output values.

---

## Common Patterns

### P1: Conflicting UDP table rows

**Problematic Code:**
```diff
// Before: conflicting UDP entries
primitive my_udp(o, a, b);
  output o; input a, b;
  table
    1 0 : 0;
    1 0 : 1;  // ERROR: conflicts with previous (same input, different output)
  endtable
endprimitive
```

**Recommended Fix:**
```diff
// After: remove the conflicting entry
primitive my_udp(o, a, b);
  output o; input a, b;
  table
    1 0 : 0;  // keep one consistent entry
    1 1 : 1;
  endtable
endprimitive
```

---

## Fix Strategy

1. Make every input combination in the UDP table map to exactly one output — remove or correct the row with the conflicting output.
2. Check for overlapping rows (including `?`/`x` wildcards) that cover the same input but disagree on output.
3. Ensure sequential UDP rows have consistent current-state/next-state entries.
4. Consider replacing the UDP with RTL logic, which is clearer and more portable.
