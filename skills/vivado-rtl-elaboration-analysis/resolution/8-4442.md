# 8-4442: BlackBox module \oproc/ddr_blender has unconnec...

**Message:** `[Synth 8-4442] BlackBox module \oproc/ddr_blender  has unconnected pin fb_vid_start_addr_in`
**Severity:** CRITICAL WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A module Vivado treats as a **black box** has an input pin left unconnected. Because
the black box has no RTL body, an unconnected input floats to an undefined/constant
value, which can silently produce incorrect hardware. The module is usually a black
box because its RTL was not found/compiled, or it is a stub/IP whose implementation
is provided elsewhere.

---

## Common Patterns

### P1: Black-box instance with an unconnected input pin

**Problematic Code:**
```systemverilog
// ddr_blender is a black box (no RTL compiled); fb_vid_start_addr_in left open
ddr_blender u_blender (
    .clk(clk),
    .pixel_in(pix)
    // fb_vid_start_addr_in : not connected -> CRITICAL WARNING
);
```

**Fix - connect every input pin of the black box:**
```systemverilog
ddr_blender u_blender (
    .clk(clk),
    .pixel_in(pix),
    .fb_vid_start_addr_in(fb_start_addr)   // drive the required input
);
```

### P2: Module should not be a black box

**Fix - add/compile the missing RTL so it is elaborated normally:**
```tcl
# Ensure the source (or IP) that defines ddr_blender is in the fileset
add_files ddr_blender.v
# or upgrade/generate the IP that provides it
```

---

## Fix Strategy

1. Connect the reported unconnected input pin to the correct driver — an unconnected black-box input floats and can corrupt results.
2. Confirm whether the module *should* be a black box; if not, add/compile its RTL (or generate/upgrade the IP) so Vivado elaborates it and can width/direction-check the pins.
3. If the pin is intentionally unused, tie it to a defined constant (`'0`/`'1`) rather than leaving it open, and document why.
4. Treat this CRITICAL WARNING as a functional risk — verify post-synthesis that the black box is driven exactly as its specification requires.
