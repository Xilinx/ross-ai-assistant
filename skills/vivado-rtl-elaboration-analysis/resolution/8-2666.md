# 8-2666: Signal Declaration in Subprogram

**Message:** `[Synth 8-2666] signal declaration is not allowed in a subprogram`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

VHDL signal declarations are not allowed inside subprograms (functions/procedures).

---

## Common Patterns

### P1: signal declared inside a subprogram

**Problematic Code:**
```diff
-- Before: signal in function
function calc return integer is
  signal s : integer;  -- ERROR: signals not allowed in functions
begin
```

**Recommended Fix:**
```diff
-- After: use variable instead
function calc return integer is
  variable v : integer;  -- variables OK in subprograms
begin
```

---

## Fix Strategy

1. Declare local objects inside functions/procedures as `variable`, not `signal` — signals are illegal in subprograms.
2. Convert any intended signal semantics (e.g., cross-process communication) to ports/signals at the architecture level, outside the subprogram.
3. Remember variables update immediately (no delta delay); adjust logic that relied on signal-update timing.
4. Keep subprograms combinational and side-effect free for clean synthesis.
