# 8-4179: divide by zero is illegal

**Message:** `[Synth 8-4179] divide by zero is illegal`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

An expression divides by zero during elaboration. This most commonly occurs when
a width/count expression uses a parameter that resolves to `0` — e.g., a port or
signal width computed as `(DATA_WIDTH / BYTE_WIDTH)` where the divisor parameter
was left at (or overridden to) `0`.

---

## Common Patterns

### P1: Parameterized width with a zero divisor

**Problematic Code:**
```systemverilog
// BYTE_WRITE_WIDTH_A defaulted/overridden to 0 -> divide by zero
input wire [(WRITE_DATA_WIDTH_A/BYTE_WRITE_WIDTH_A)-1:0] wea,
```

**Fix - ensure the divisor parameter is non-zero:**
```systemverilog
parameter WRITE_DATA_WIDTH_A = 32;
parameter BYTE_WRITE_WIDTH_A = 8;   // must be > 0 and divide the data width
input wire [(WRITE_DATA_WIDTH_A/BYTE_WRITE_WIDTH_A)-1:0] wea;
```

### P2: Guard the computation defensively

**Fix - clamp the divisor so elaboration cannot divide by zero:**
```systemverilog
localparam BWW = (BYTE_WRITE_WIDTH_A == 0) ? 1 : BYTE_WRITE_WIDTH_A;
input wire [(WRITE_DATA_WIDTH_A/BWW)-1:0] wea;
```

---

## Fix Strategy

1. Find the division in the reported expression and identify which parameter/generic is the divisor.
2. Set that parameter to a valid non-zero value at instantiation (and give it a sensible non-zero default in the module).
3. Verify the divisor actually divides the dividend (e.g., `WRITE_DATA_WIDTH_A` must be a multiple of `BYTE_WRITE_WIDTH_A`) so the width is a whole number.
4. If the parameter can legitimately be zero in some configuration, guard the expression (`(D==0)?1:D`) or use a `generate` to handle that case explicitly.
