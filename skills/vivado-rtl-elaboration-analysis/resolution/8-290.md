# 8-290: Fork/Join as Sequential

**Message:** `[Synth 8-290] fork/join block will be implemented as sequential block`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A `fork`/`join` block is converted to sequential execution for synthesis.

---

## Common Patterns

### P1: fork/join used for parallelism

**Problematic Code:**
```diff
fork
  begin ... end
  begin ... end
join  // WARNING: runs sequentially
```

**Recommended Fix:**
```diff
// Replace with sequential always block
always @(posedge clk) begin
  ...
end
```

---

## Fix Strategy

1. Rewrite the `fork`/`join` body as ordinary sequential statements inside a single `always` block, or split it into multiple concurrent `always` blocks / continuous assignments for real hardware parallelism.
2. Remember that hardware is inherently parallel — separate `always @(posedge clk)` blocks already run "in parallel", so `fork`/`join` is unnecessary for synthesis.
3. `fork`/`join_none` and `join_any` are simulation-only; if they belong to a testbench, guard them with `// synthesis translate_off` / `translate_on` or move them out of synthesizable RTL.
4. Verify the sequentialized order preserves the intended data dependencies before/after the conversion.
