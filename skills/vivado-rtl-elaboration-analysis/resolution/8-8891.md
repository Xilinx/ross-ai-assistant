# 8-8891: Already Declared

**Message:** `[Synth 8-8891] '!%1!' is already declared`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

An identifier is declared more than once in the same scope.

---

## Common Patterns

### P1: Duplicate / reserved-name declaration

**Problematic Code:**
```diff
// Before: duplicate declaration
logic bit;  // ERROR: 'bit' is a built-in type, already declared
```

**Recommended Fix:**
```diff
// After: use unique name
logic my_bit;  // unique name, no conflict
```

### P2: Name imported from a package clashes with a local declaration

**Problematic Code:**
```systemverilog
package pkg; localparam WIDTH = 8; endpackage
import pkg::*;
module m;
  localparam WIDTH = 16;   // ERROR: 'WIDTH' is already declared (via import)
endmodule
```

**Recommended Fix — qualify or rename to avoid the wildcard-import clash:**
```systemverilog
module m;
  localparam LOCAL_WIDTH = 16;      // distinct local name
  localparam PKG_WIDTH = pkg::WIDTH; // reference the package member explicitly
endmodule
```

### P3: Same name declared in two included/compiled files

**Problematic Code:**
```systemverilog
`include "defs.svh"   // defs.svh declares: typedef logic [7:0] byte_t;
typedef logic [15:0] byte_t;   // ERROR: 'byte_t' is already declared
```

**Recommended Fix — declare the type once, in a single shared header:**
```systemverilog
`include "defs.svh"   // keep the single authoritative typedef
// remove the duplicate local typedef
```

---

## Fix Strategy

1. Rename the identifier so it does not clash with a built-in type/keyword (e.g., `bit`) or an existing declaration in the same scope.
2. Search the scope for the earlier declaration of the same name and remove/rename the duplicate.
3. Avoid reserved words as identifiers; pick descriptive, unique names.
4. If two units legitimately need the name, qualify them by scope/package rather than redeclaring.
