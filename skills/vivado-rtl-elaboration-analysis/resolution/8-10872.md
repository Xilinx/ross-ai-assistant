# 8-10872: Null Literal Type Mismatch

**Message:** `[Synth 8-10872] illegal use of NULL literal; expected integer/type`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Vivado Message

```
ERROR: [Synth 8-10872] illegal use of NULL literal; expected integer/type [/path/to/file:NN]
```

---

## Root Cause

VHDL `null` is used where a specific type value is expected. `null` is only valid for access types.

---

## Common Patterns

### P1: null assigned to a non-access type

**Problematic Code:**
```diff
-- Before: null used as integer generic value
package nibble is new work.my_pac
  generic map(datawidth => null);  -- ERROR: null not valid for integer
```

**Recommended Fix:**
```diff
-- After: provide an actual integer value
package nibble is new work.my_pac
  generic map(datawidth => 4);     -- provide integer value
```

---

## Fix Strategy

1. `null` is valid only for access (pointer) types — provide a real value of the expected type instead.
2. If the code relied on null pointers/dynamic objects, that is not synthesizable; redesign with fixed structures.
3. Initialize the object with a defined default value of its type.
4. Keep any genuine access-type/null usage in simulation-only code.
