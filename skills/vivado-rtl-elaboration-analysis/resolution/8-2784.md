# 8-2784: Aggregate Type Ambiguous

**Message:** `[Synth 8-2784] type of aggregate cannot be determined without context ; !%1! visible types match here`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A VHDL aggregate cannot be uniquely typed — no visible type matches or multiple types match.

---

## Common Patterns

### P1: Aggregate with no unique type

**Problematic Code:**
```diff
-- Before: ambiguous aggregate
signal s : std_logic_vector(3 downto 0);
s <= (others => '0');  -- May ERROR if context is ambiguous
```

**Recommended Fix:**
```diff
-- After: add type qualification
s <= std_logic_vector'(others => '0');  -- explicit type
-- Or ensure only one matching type is visible
```

---

## Fix Strategy

1. Qualify the aggregate with an explicit type (`std_logic_vector'(others => '0')`) so the tool knows exactly which type it is.
2. Ensure only one matching type is visible in scope; remove ambiguous `use` clauses that bring in competing candidate types.
3. Provide enough context (e.g., assign to a typed target directly) so the aggregate's type is inferable.
4. For record/array aggregates, use named associations to pin down the intended type and fields.
