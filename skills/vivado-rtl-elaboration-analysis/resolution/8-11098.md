# 8-11098: Range Attribute on Non-Scalar/Non-Array Type

**Message:** `[Synth 8-11098] prefix of attribute 'range' should denote a scalar or array type`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Vivado Message

```
ERROR: [Synth 8-11098] prefix of attribute 'range' should denote a scalar or array type [/path/to/file:NN]
```

---

## Root Cause

The VHDL `'range` attribute is applied to an object whose type is neither scalar
nor array — for example, a generic type parameter that could be a record or other
non-iterable type.

---

## Common Patterns

### P1: 'range on an unconstrained generic type

**Problematic Code:**
```diff
-- Before: 'range on unconstrained generic type
generic (type t1);
function f1(in1 : t1) return t1 is
begin
  for idx in in1'range loop   -- ERROR: t1 may not be array/scalar
    ...
  end loop;
end;
```

**Recommended Fix:**
```diff
-- After: constrain generic to array type
generic (type t1 is array (natural range <>) of std_logic);
function f1(in1 : t1) return t1 is
begin
  for idx in in1'range loop   -- OK: t1 is now constrained to array
    ...
  end loop;
end;
```

---

## Fix Strategy

1. Constrain the generic type to an array (or scalar with a range) so `'range` is valid on it.
2. Alternatively, pass the range/bounds as separate generic parameters and use explicit loop bounds.
3. Do not apply `'range` to an unconstrained/opaque generic type.
4. Confirm the flow supports the VHDL-2008 generic-type construct; otherwise use a concrete array type.
