# 8-3391: Cannot Infer RAM

**Message:** `[Synth 8-3391] Unable to infer a block/distributed RAM for '!%1!' because the memory pattern used is not supported. Failed to dissolve the memory into bits because the number of bits (!%2!) is too large. Use 'set_param synth.elaboration.rodinMoreOptions {rt::set_parameter dissolveMemorySizeLimit !%3!}' to allow the memory to be dissolved into individual bits`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

RTL coding pattern doesn't match supported Block/Distributed RAM templates.

---

## Common Patterns

### P1: Asynchronous-read RAM pattern

**Problematic Code:**
```diff
// Before: unsupported RAM pattern
always @(posedge clk)
  if (we) mem[addr] <= din;
assign dout = mem[addr2];  // async read with write
```

**Recommended Fix:**
```diff
// After: follow UG901 RAM template
always @(posedge clk) begin
  if (we) mem[addr] <= din;
  dout <= mem[addr];  // synchronous read
end
```

---

## Fix Strategy

1. Follow a Vivado RAM inference template (UG901): a clocked process that writes on a clock edge and reads **synchronously** (registered output).
2. Remove asynchronous reads (`assign dout = mem[addr];` outside a clocked block) — they force LUT/distributed logic and defeat BRAM inference.
3. Keep write and read in a consistent, supported style (read-first/write-first/no-change) and avoid mixing async and sync accesses to the same memory.
4. If inference still fails, use the Block Memory Generator IP or set `ram_style`/`rom_style` to force the desired implementation.
