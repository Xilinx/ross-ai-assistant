# 8-6046: Multiple Drivers via Hierarchical Name

**Message:** `[Synth 8-6046] Another driver is found for the item '!%1!' referred by hierarchical name`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A signal is driven multiple times when hierarchical name references are resolved.

---

## Common Patterns

### P1: Extra driver via hierarchical name

**Problematic Code:**
```diff
-- Before: multiple drivers through hierarchy
sig <= val1;
<<signal inst.sig>> <= val2;  -- ERROR: double driver through external name
```

**Recommended Fix:**
```diff
-- After: single driver
sig <= val1;  -- remove hierarchical write
-- External names are not synthesizable anyway
```

---

## Fix Strategy

1. Remove external/hierarchical-name assignments (`<<signal ...>>` / cross-module writes) — they are not synthesizable and create extra drivers.
2. Give the signal a single driver in its owning scope and route the value through ports for inter-module communication.
3. Consolidate the conflicting drivers into one (mux/priority) if multiple sources were intended.
4. Verify the signal ends up with exactly one driver after removing the hierarchical write.
