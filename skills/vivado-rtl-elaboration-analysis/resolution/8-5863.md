# 8-5863: Implementing Library version of Mod/Rem due

**Message:** `[Synth 8-5863] Implementing Library version of Mod/Rem due to signed path. This typically leads to poor QOR. Check RTL to see if unsigned path for the operator is possible`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A `mod`/`rem` (or `/`) operator is applied to a **signed** operand, so Vivado
uses the slower library implementation of the operator, which yields poor QoR.
An unsigned operand allows the more efficient implementation.

---

## Common Patterns

### P1: Signed operand forces slow mod/rem

**Problematic Code:**
```diff
-- Problematic line:
--printf("\n_corr correlator real-time coeffs loading done...\n_corr");
				else
					coeff_cnt <= (coeff_cnt - 1) mod n_corr;
				end if; -- coeff_cnt
```

**Recommended Fix:**
```vhdl
-- Use an unsigned operand (value is known non-negative) for efficient mod:
if coeff_cnt = 0 then coeff_cnt <= n_corr - 1;   -- counter wrap, no signed mod
else                 coeff_cnt <= coeff_cnt - 1;
end if;
```

---

## Fix Strategy

1. Perform `mod`/`rem`/`/` on **unsigned** operands when the value is known non-negative — this selects the efficient implementation instead of the slow signed library version.
2. Replace `mod` by a constant with a counter-wrap (`if cnt=0 then cnt<=N-1; else cnt<=cnt-1;`) to avoid the operator entirely.
3. Cast operands with `unsigned(...)`/`to_integer(unsigned(...))` where appropriate, ensuring the value cannot be negative.
4. This is a QoR warning — fixing it improves timing/area; verify functional equivalence after switching to unsigned.
