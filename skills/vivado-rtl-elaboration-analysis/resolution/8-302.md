# 8-302: Global Signal Treated as Local

**Message:** `[Synth 8-302] global signal treated as architecture-local`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A VHDL signal that could be shared globally is treated as local to the architecture.

---

## Common Patterns

### P1: Architecture-local signal

**Problematic Code:**
```diff
signal c : std_logic;  -- WARNING: treated as local
```

**Recommended Fix:**
```diff
-- This is usually expected behavior in synthesis
-- No fix typically needed
```

---

## Fix Strategy

1. This is usually informational — Vivado scopes signals locally during synthesis and no change is required for correct behavior.
2. If you intended a signal to be shared across modules, do not rely on global/shared-variable semantics; connect it explicitly through module ports.
3. Avoid VHDL shared variables for cross-process communication in synthesizable code — use signals with well-defined drivers instead.
4. Confirm the design does not depend on simulation-only global visibility; if it does, refactor to explicit port connections.
