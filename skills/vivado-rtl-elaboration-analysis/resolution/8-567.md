# 8-567: Missing Sensitivity List Signal

**Message:** `[Synth 8-567] referenced signal should be on the sensitivity list`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A signal read inside a process/always is not in the sensitivity list.

---

## Common Patterns

### P1: Signal read but missing from sensitivity list

**Problematic Code:**
```diff
// Before: out1 read but not in sensitivity
always @(in1)
  out1 = in1 & out1;  // WARNING: out1 missing
```

**Recommended Fix:**
```diff
// After: add to sensitivity list or use @(*)
always @(*)
  out1 = in1 & prev_out;
```

---

## Fix Strategy

1. Use `always @(*)` (or `always_comb`) for combinational logic so the sensitivity list is inferred automatically and stays complete.
2. If you keep an explicit list, add **every** signal read in the block; an incomplete list causes simulation/synthesis mismatch.
3. Do not include a signal that is only assigned (not read) — restructure so you read the intended value (e.g., a registered `prev_out`) rather than the same signal being written.
4. Verify the logic is truly combinational; if state is intended, move it into a clocked block instead.
