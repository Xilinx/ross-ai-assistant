# 8-2068: Guarded Assignment Outside Guarded Block

**Message:** `[Synth 8-2068] guarded signal assignment is not in a guarded block`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A VHDL guarded signal assignment (`<= guarded`) is used outside a block with a guard expression.

---

## Common Patterns

### P1: guarded assignment without a guard

**Problematic Code:**
```diff
-- Before: guarded assignment without guard
out1 <= guarded in1;  -- ERROR: not in guarded block
```

**Recommended Fix:**
```diff
-- After: add guard or remove 'guarded'
out1 <= in1;  -- remove guarded keyword
-- Or add a guarded block:
blk: block (enable = '1') is
  out1 <= guarded in1;
end block;
```

---

## Fix Strategy

1. Remove the `guarded` keyword from the signal assignment if no guard is intended — a plain `out1 <= in1;` is the usual fix.
2. If gating is intended, place the assignment inside a `block` that declares a guard expression (`blk: block (enable = '1') is ... out1 <= guarded in1; end block;`).
3. Prefer modeling the gating explicitly with an `if`/process (e.g., enable-controlled register) rather than guarded blocks, which are rarely used and can be non-synthesizable.
4. Verify the resulting behavior matches the intended enable/gating semantics.
