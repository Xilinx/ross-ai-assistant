# 8-11218: Invalid Time Literal Value

**Message:** `[Synth 8-11218] time literal !%1! must have value 1, 10 or 100`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A SystemVerilog time literal must have a value of 1, 10, or 100 with a time unit.

---

## Common Patterns

### P1: Time literal in synthesizable RTL

**Problematic Code:**
```diff
// Before: invalid time literal
reg delay = 1000fs;  // ERROR: must be 1, 10, or 100
```

**Recommended Fix:**
```diff
// After: use valid time literal or parameter
localparam DELAY = 1;  // time values not synthesizable
// For synthesis, use integer counters instead of time literals
```

---

## Fix Strategy

1. Time literals (`10ns`, etc.) are not synthesizable — replace them with integer parameters or clock-cycle counts.
2. Express delays as a number of clock cycles counted in a clocked process.
3. Move any real timing modeling into the testbench.
4. Parameterize cycle counts so timing is configurable without time literals.
