# 8-1718: Unpacked to Packed Assignment

**Message:** `[Synth 8-1718] cannot assign !%1! type to !%2! type`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

An unpacked type value is assigned to a packed type variable without proper conversion.

---

## Common Patterns

### P1: Unpacked assigned to packed without conversion

**Problematic Code:**
```diff
// Before: unpacked assigned to packed
int arr[4];  // unpacked
logic [127:0] packed_val;
packed_val = arr;  // ERROR
```

**Recommended Fix:**
```diff
// After: use streaming operator or concatenation
packed_val = {arr[3], arr[2], arr[1], arr[0]};  // explicit
// Or: packed_val = {>>{arr}};  // streaming operator
```

---

## Fix Strategy

1. Convert unpacked to packed explicitly — use concatenation with a defined bit order (`{arr[3], arr[2], arr[1], arr[0]}`) or the streaming operator (`{>>{arr}}` / `{<<{arr}}`).
2. Choose the stream direction (`>>` vs `<<`) deliberately so the bit/element ordering matches your intended layout.
3. Ensure the total bit width of the unpacked source equals the packed target width before converting.
4. Where possible, declare the data as a packed array from the start to avoid the conversion entirely.
