# 8-2121: Illegal Context for Real

**Message:** `[Synth 8-2121] illegal context for real expression`
**Severity:** ERROR
**Source:** Oasys Synthesis

---

## Root Cause

A `real` type is used in a context where it's not allowed (e.g., in bit operations, ports in Verilog mode).

---

## Common Patterns

### P1: real used in an integer-only context

**Problematic Code:**
```diff
// Before: real in illegal context
real r;
assign out = r & mask;  // ERROR: bitwise on real
```

**Recommended Fix:**
```diff
// After: use integer or fixed-point
logic [31:0] r;
assign out = r & mask;  // integer type works
```

---

## Fix Strategy

1. Do not use `real` in bit/logic operations, ports (Verilog), or other integer-only contexts — replace it with an integer or fixed-point (scaled integer) representation.
2. For synthesizable arithmetic, model fractional values as fixed-point using `logic [N-1:0]` with an agreed binary point.
3. Keep genuine `real` computation in simulation/parameter contexts only, and derive synthesizable integer constants from it at elaboration.
4. If a real parameter must configure hardware, convert it to an integer/fixed-point constant before use in RTL.
