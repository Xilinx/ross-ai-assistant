# 8-3848: Undriven Net

**Message:** `[Synth 8-3848] Net does not have driver`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

A signal/net has no driver — it's declared but never assigned.

---

## Common Patterns

### P1: Declared signal with no driver

**Problematic Code:**
```diff
-- Before: undriven signal
signal ReaderRdSop : std_logic;  -- WARNING: no driver
```

**Recommended Fix:**
```diff
-- After: add a driver or remove if unused
ReaderRdSop <= some_signal;  -- add driver
-- Or remove the signal if not needed
```

---

## Fix Strategy

1. Drive the net from exactly one source (an `assign`, process, or instance output); an undriven net floats to a constant and often breaks intended behavior.
2. If the signal is genuinely unused, remove its declaration and any partial references to it.
3. Check for a typo where the intended driver assigns a differently-named signal, leaving this one undriven.
4. For top-level inputs that are legitimately unused, that is expected; for internal nets, an undriven net is almost always a bug.
