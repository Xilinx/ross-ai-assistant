# 8-7134: Asynchronous Set/Reset value of 'Z' to

**Message:** `[Synth 8-7134] Asynchronous Set/Reset value of 'Z' to reg 'info_reg' will be ignored`
**Severity:** WARNING
**Source:** Oasys Synthesis

---

## Root Cause

An asynchronous set/reset assigns a tristate value (`'Z'`) to a register. A
flip-flop's set/reset can only force `0` or `1`, so the `'Z'` reset value is
ignored, which can cause a simulation/synthesis mismatch.

---

## Common Patterns

### P1: 'Z' as an async set/reset value

**Problematic Code:**
```diff
-- Asynchronous Set/Reset value of 'Z' to reg 'info_reg' will be ignored
```

**Recommended Fix:**
```verilog
// Reset the register to 0/1 only; model 'Z' with an output tri-state buffer
always @(posedge clk or negedge rst_n)
  if (!rst_n) info_reg <= 1'b0;      // defined reset value, not 'Z'
  else        info_reg <= info_nxt;
assign info_pad = oe ? info_reg : 1'bz;   // tri-state at the pad
```

---

## Fix Strategy

1. Never drive a register's async set/reset with `'Z'` — use a defined `0`/`1` reset value; the `'Z'` is ignored and causes sim/synth mismatch.
2. Model any high-impedance behavior with an explicit output tri-state buffer at the pad (`pad <= q when oe else 'Z';`), separate from the register.
3. Ensure the reset expression yields only logic levels, not metavalues.
4. Verify the register's reset behavior matches simulation after removing the `'Z'`.
