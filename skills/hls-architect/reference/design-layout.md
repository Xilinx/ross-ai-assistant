# Design Layout

Manages the canonical directory workspace for an HLS design as it progresses through the
conversion pipeline. Called by `/matlab-to-cpp` and `/hls-architect` — never run manually
unless inspecting or recovering a workspace.

---

## Canonical Tree

```
design_name/
├── frame_based/          ← INPUT (created by /matlab-to-cpp OR standalone /hls-architect)
│   ├── kernel.cpp
│   └── testbench.cpp
└── rearchitect/
    ├── v1/               ← V1: first architecture (created by /hls-architect)
    │   ├── src/          ← kernel_hls.cpp
    │   ├── tb/           ← testbench.cpp (copied from frame_based/)
    │   └── hls_config.cfg
    │   └── vitis-comp.json
    └── v2/               ← V2: alternative architecture (optional, if /hls-architect creates it)
        ├── src/          ← kernel_hls.cpp
        ├── tb/           ← testbench.cpp (copied from frame_based/)
        └── hls_config.cfg
        └── vitis-comp.json
```

`design_name` = workspace root name (from matlab-to-cpp or derived from source filename).

---

## Stage Definitions

| `stage` arg | Directories created | Extra files written |
|---|---|---|
| `rearchitect_v1` | `design_name/rearchitect/v1/src/`<br>`design_name/rearchitect/v1/tb/` | `hls_config.cfg` template |
| `rearchitect_v1` | `design_name/rearchitect/v1/src/`<br>`design_name/rearchitect/v1/tb/` | `vitis-comp.json` template |
| `rearchitect_v2` | `design_name/rearchitect/v2/src/`<br>`design_name/rearchitect/v2/tb/` | `hls_config.cfg` template |
| `rearchitect_v2` | `design_name/rearchitect/v2/src/`<br>`design_name/rearchitect/v2/tb/` | `vitis-comp.json` template |
| `show` | (nothing created) | prints expected tree |

---

## Behavior

### For any stage (except `show`)

1. Receive `design_name` and `stage` from the calling skill's context
2. Look up the stage in the table above
3. Create directories with parents:
   ```bash
   mkdir -p <path>
   ```

4. For `rearchitect_v1` and `rearchitect_v2`: write `hls_config.cfg` template into the version root:

   ```ini
   # Generated by /design-layout — fill in TOP_FUNCTION, PART, CLOCK before synthesis
   [hls]
   syn.top=<TOP_FUNCTION>
   syn.part=<XPART>
   syn.clkPeriod=<CLOCK_NS>ns
   ```

   Caller (`/hls-architect`) is responsible for filling in TOP_FUNCTION, PART, and CLOCK after writing.


   5. For `rearchitect_v1` and `rearchitect_v2`: write `vitis-comp.json` template into the version root:

   ```ini
   # Generated by /design-layout — fill in TOP_FUNCTION, PART, CLOCK before synthesis    
   {
   "name": <design_name>,
   "type": "HLS",
   "configuration": {
    "componentType": "HLS",
    "configFiles": ["./hls_config.cfg"],
    "work_dir": <TOP_FUNCTION>
   }
   }
   ```

   Caller (`/hls-architect`) is responsible for filling in TOP_FUNCTION after writing.

6. Print confirmation — example for `rearchitect_v1`:
   ```
   [design-layout] Created design_name/rearchitect/v1/
     ├── src/            ← write kernel source here
     ├── tb/             ← write testbench here
     └── hls_config.cfg  ← fill in TOP_FUNCTION, PART, CLOCK
     └── vitis-comp.json      ← fill in TOP_FUNCTION
   ```

7. Return the root path of the created stage directory to the calling skill.

### For `stage=show`

Print the full expected tree without creating anything:

```
[design-layout] Workspace for design_name (architect stages):
design_name/
├── frame_based/     ← INPUT (assumed to exist)
└── rearchitect/
    ├── v1/  → src/  tb/  hls_config.cfg vitis-comp.json
    └── v2/  → src/  tb/  hls_config.cfg  (created only if V2 is applicable) vitis-comp.json
```

## Callers

| Skill | When it calls | Stage |
|---|---|---|
| `/hls-architect` | Step 2d (Write to rearchitect) | `rearchitect_v1` |
| `/hls-architect` | Optional: if V2 architecture created | `rearchitect_v2` |

---

## Rules

- **Never create directories outside `design_name/`**
- **Never overwrite existing directories** — if the directory already exists, print a warning and skip creation; do not delete existing content
- **Never create `rearchitect/v2/` if V2 = N/A** — architect must explicitly call this skill; absence of the call means V2 was not generated
- **`hls_config.cfg` is a template** — always write it with `<PLACEHOLDER>` values; the calling skill fills in the actual values
- **`vitis-comp.json` is a template** — always write it with `<PLACEHOLDER>` values; the calling skill fills in the actual values immediately after
