# Plan codes

Rejections and warnings printed by `ila::plan`. Source: `scripts/ila_qualify.tcl` (`qualify`) and `scripts/ila_plan.tcl` (`plan`).
There is no N09 or N11. For the user, in plain words with what to do: `help.md`, section refusals.

## Rejections

| Code | Meaning |
|---|---|
| N01 | Name not in the netlist. A "Did you mean" list follows when names are close. When the same name exists elsewhere in the design, the reason lists where: "nothing in the netlist matches 'count' at the top level. count exists in: u_a/u_b/u_c, u_a/u_s. Name it with its path (for example u_a/u_b/u_c/count), or */count for every instance." Nothing is picked for the user: ask which one, or ask again with the path. Also raised for a combinational name that matched only register outputs (no combinational net). For a request by the marked nets (`-filter {MARK_DEBUG}`) with nothing marked, the reason says no net carries MARK_DEBUG (or a block-design Debug tag) and shows how to ask by name, with its path. |
| N02 | Net has no driver, or is a LUT fed only by undriven nets (a kept wire in synthesis). |
| N03 | Not a plain signal (net type is not SIGNAL). |
| N04 | Clock net (it drives clock pins). |
| N05 | Constant, or a LUT fed only by constants (a kept wire in synthesis). |
| N06 | Inside a debug core. |
| N07 | No capture clock found (combinational with no clocked startpoint, driver has no clock pin, or comes straight from an input port). |
| N08 | Driven from more than one clock net. |
| N10 | Too much on one clock for one ILA. One signal is wider than one probe port: the message names the signal, the family and its limit, 4096 bits on UltraScale and UltraScale+ (PG172), 1024 on Versal (PG357). Or more than 65,536 probe bits on one UltraScale or UltraScale+ core (PG172). Or probe ports (one per signal) times comparators over 1024 (IP_Flow 19-3478): the message names the ports, the comparators and the product. Also raised for a user `-max_probe_bits` below the bits on the clock. |
| N12 | Net on an output port. Vivado silently refuses it. Probe the register or logic net that feeds the port. |
| N13 | Net between synchronizer registers (ASYNC_REG). Vivado refuses it (Chipscope 16-3). Probe the last stage instead. |
| N15 | Hardened connection with no fabric route (for example CIPS to NoC). It fails at route. When every net of a name is refused N15 or N07 and the same signal name is on a fabric net that can be probed, the first refusal says where: "S00_AXI_awaddr exists on a fabric path, which can be probed, in: top_i/axi_noc_0. Name it with its path (for example top_i/axi_noc_0/S00_AXI_awaddr)." Ask the user, or plan that path when it is clearly what they meant, and say so. |
| N16 | Combinational net skipped by a wildcard request. |
| N17 | Request too broad (unscoped match-all or wildcard names over the 1024-bit limit, or a combinational `*`). Module-scoped wildcards are exempt. |
| N18 | The request targets a DFX partition that holds no logic (greybox or black box). Nothing to insert; `plan` returns 0 and `apply` has nothing to do. |
| N19 | Versal DFX: the clock net of the request has no name inside the reconfigurable partition, so an ILA in the partition cannot take it as its clock. Not inserted. Ask the user which clock inside the partition to use. |
| N20 | An existing debug core already probes this net (or another name of it). Skipped, not probed twice: a second probe costs block RAM and renames the bus in the `.ltx`. The message is `<net> is already probed by <core>. Skipped, so the net is not captured twice ...`. Plan with `-allow_duplicate 1` to probe it again (ask the user first). With `-replace_existing 1` the nets of the cores being replaced do not count. If every requested net is skipped, `apply` ends `ILA_NOTHING_INSERTED` and the plan lists each N20. |
| N99 | Vivado silently skipped the net when connecting it. `ila::apply` drops it and builds the core again with the rest. |

## Warnings

| Code | Meaning |
|---|---|
| W01 | A combinational net that was named was accepted. Its captured value can glitch. |
| W02 | Memory budget not checked: the part reports no block RAM count (or no UltraRAM count for `-memory_type uram`), or a DFX partition has no pblock. Printed as `WARNING W02: budget NOT checked: ...` (`partition budget NOT checked: ...` for a partition); the session facts (kept in memory, no file is written) has `budget_checked` 0 for the part case. The plan is not refused. |
| A01 | Alias of a net already in the plan (same electrical net). Probed once. |

## Notes (printed as `NOTE`, never refuse anything)

| Code | Meaning |
|---|---|
| M01 | State of `config_flows -mark_debug` in this session (enable, disable, synthesis_only). `disable` and `synthesis_only` print a WARNING: MARK_DEBUG nets may have been optimized away. The setting is not stored in a checkpoint. When `disable` or `synthesis_only` is set and a named net or the marked nets are not in the netlist (N01), the N01 text adds: "If this net should have been kept, check the config_flows -mark_debug setting (<mode> drops it from the netlist); the checkpoint alone cannot tell the cause." |
| M02 | MARK_DEBUG is on every bit of a bus and the request names only some bits (UG901: one bit marks the whole bus). |
| M03 | An accepted net carries MARK_DEBUG and sits in a partially driven vector (AR 000040253). |
| M04 | A probed net is on the boundary of a reconfigurable partition (DFX) and shows DONT_TOUCH (UG909: HD.RECONFIGURABLE sets it on the partition cell and its interface nets). Not refused: Vivado accepted such nets in a Versal DFX run. Tell the user the net is on the interface and, if Vivado refuses it at apply, probe a register inside the module. Printed only when the netlist shows the property. |
| M05 | UltraScale+ DFX on 2026.2 or later, a static core: a probed net is inside a partition and not on its boundary. Vivado adds one partition port per such net, so the static design links only the RM that was probed. Measured (one KU5P design, 2026.2): 32 probed bits with 24 inside the RM gave `Netlist 29-77` (24 ports missing) for a second RM. The same request limited to the 8 boundary nets linked a second RM and went through route, bitstream and `pr_verify`. A warning, not a refusal. Tell the user to probe boundary nets if a second RM must link. |
| D01 | UltraScale+ DFX design on Vivado 2026.2 or later: the skill does not refuse from the version alone, and goes on only when the design carries no debug core and no S_BSCAN port yet. Cores go in the static part and probe partition nets across the boundary. Proven in software for one KU5P design with no debug before the insertion, through route, DRC, probes file, full and partial bitstreams, grey child and `pr_verify`. Also board runs on KCU116, VCU108 and VCU128, 2026.2 daily builds: full image and up to five partial swaps, the ILA captured after each. Not proven: a design that already carries debug ports or cores (the skill refuses it: `ILA_BLOCKED_DFX_UNSUPPORTED` with "the skill's refusal", or `ILA_BLOCKED_DFX_NO_BSCAN` / `ILA_REFUSED_FLAGGED`), a second RM under a core that probes RM-internal nets (the link fails, Netlist 29-77), boards other than KCU116, VCU108 and VCU128, other parts, project mode. Printed once by `plan` when a request touches a partition, and by the static-first route for a flagged design. 2026.1 and earlier refuse (`ILA_BLOCKED_DFX_NO_BSCAN`, `ILA_REFUSED_FLAGGED`). An unreadable version counts as 2026.1. |
| A02 | A probed net has other names. Gives the canonical name (fewest hierarchy levels). Any name is accepted in a request. |
| C01 | The capture or hub clock comes from an MMCM or PLL. WARNING when its LOCKED output is not connected, NOTE with the load count when it is. Connectivity only. |
| C02 | Hub clock report: net, period, source, free-running verdict, 100 MHz advice (non-Versal), JTAG 2.5x rule, Versal S_AXI note. On Versal, when the hub clock pin has no driver (Vivado 2026.2 after opt_design), one note says the clock cannot be determined and what to check; no clock is named. |
| C03 | WARNING. A debug hub that was already in the design is left on its clock (the skill moves only a hub it created). Printed when that clock is not a free-running ILA clock and cannot be traced to a free source: it may stop and the hub link can die. A NOTE `pre-existing debug hub left on <net>` is always printed; the session facts (kept in memory, no file is written) has `hub_clock_preexisting` 1. |
| C04 | WARNING. Versal only. After `create_debug_core` the AXI debug hub clock `axi_dbg_hub/aclk` had no driver (Vivado 2026.2 synthesized checkpoint), so `opt_design` would drop the hub connections. The skill connected it to the free ILA clock, as Vivado 2026.1 does, and names the clock. A hub that was already in the design is never changed. |

N02, N05 and N07 evidence for a bit of a vector lists the state of every bit of the vector and says when it is partially driven.

## Library errors (not plan codes)

- `ILA_REFUSED_PLACED`: input has placed cells (placed or routed). Give the synthesized design. `ila::check_input -allow_state_reset 1` goes on with a warning (`opt_design`, `place_design` and `route_design` must run again); set it only when the user asked to change the design as it is. `ila::change` counts placed cells itself and never takes the override: a setting change there drops the core's placement without a message, and a Versal design then cannot be placed again.
- `ILA_REFUSED_IMPL_RUN`: the open design is the implementation run of a project (Vivado 12-4097). The override does not apply. Open the synthesized design (`open_run synth_1`).
- `ILA_BAD_OPTION`: `check_input` got an option it does not know, or a value that is not 0 or 1.
- `ILA_BLOCKED_NO_CIPS`: Versal design without a `PS9` or `PS11` cell (blocker FB-V01; `PS11` is the PS Wizard processor). Also raised when Vivado error 12-727 says it found no `versal_cips` IP. The IP must also have a PL (fabric) reset enabled. Other 12-727 texts are different causes: the library reads the text after the id, not the id.
- `ILA_BLOCKED_DFX_NO_BSCAN`: `plan` was asked to probe inside a reconfigurable partition (DFX) that lacks the 12 `S_BSCAN_*` boundary ports (UltraScale+). Report it with its required change (add the 12 ports to every RM, leave them open on the instance in static, instantiate the ILA in the RM, re-synthesize static and every RM). Ports alone do not enable insertion. Add nothing.
- `ILA_BLOCKED_DFX_NO_HUB`: Versal DFX. Raised by `plan` when a request targets a reconfigurable module with no AXI Debug Hub, or the static part when no hub sits outside the partitions. A request that probes only a module is refused too when the static part has no hub. Also raised when `create_debug_core` fails with 12-727 "Everest debug hub can not be inserted in RP region" (the partition or module has no hub; a greybox has none and cannot take an ILA). Required change: a hub must exist in that partition or module. Put an AXI Debug Hub in the module source. Add nothing.
- `ILA_BLOCKED_DFX_UNSUPPORTED`: Vivado error 17-69 with the text "reconfigurable partition ... Debug insertion is not currently supported". Other 17-69 texts (it is a generic wrapper id) stay `ILA_CREATE_FAILED`. Required change: Vivado does not insert debug cores into reconfigurable partitions (UG909 Configuration Debugging). Instantiate the ILA in the module source. UltraScale+: the partition needs the 12 `S_BSCAN_*` ports and Vivado infers the hubs (hubs cannot be instantiated). Versal: hubs are AXI Debug Hubs that the user places. The text says which ports and cores are already there. Add nothing.
- `ILA_BLOCKED_DFX_STATIC_IN_CHILD`: Versal DFX project, `plan` was asked to probe the static part while a child configuration is open. The project run of a child does not read the static debug XDC, so a static core added there is silently dropped. Report the required change: add static cores while the parent configuration is open, then re-implement the parent run. Requests that probe only a reconfigurable module are fine in a child. Add nothing. Not raised on a checkpoint outside a project, where the role cannot be told.
- `ILA_NOT_APPLIED`: a step that needs the cores of `ila::apply` (`ila::next_steps`, `ila::write_probes`) found none made in this session (apply has not run, or `ila::reset` removed them). Run `ila::apply` first. Nothing was run and nothing was written.
- `ILA_APPLY_FAILED`: `ila::next_steps` was called after an `ila::apply` that failed. The design holds some of the planned cores, not all. Nothing was run and nothing was written. Run `ila::reset`, fix the cause that `ila::apply` named, then `ila::plan` and `ila::apply` again.
- `ILA_DEPTH_RANGE`, `ILA_OPTION_RANGE`: option value not accepted by `ila::plan` or `ila::change` (a non-integer for an integer option, also `-memory_type uram` off Versal or below depth 4096, and a `-name_prefix` with anything but letters, digits and underscore). `-comparators` must be 1 to 16 and is accepted only with advanced trigger or storage qualification on (D8, as in the Vivado wizard); `-probe_type` takes `data` or `data_and_trigger`. `ila::change` checks every value before it calls Vivado.
- `ILA_PROPERTY_MISMATCH`: Vivado accepted a `set_property` on a debug core or port and reads back another value (Versal `C_TRIGIN_EN true` stays false). `apply` removes the half-made core and stops. `ila::change` stops and says which settings it had already set.
- `ILA_OPTION_UNSUPPORTED`: `ila::plan` or `ila::change` was asked for trigger in or out (`-trigin 1`, `-trigout 1`; the message names `C_TRIGIN_EN` and `C_TRIGOUT_EN`). Measured: UltraScale+ reads the setting back as true and builds `C_TRIGIN_EN=0`; Versal reads false; unconnected trigger ports fail. Nothing is planned or changed.
- `ILA_CHANGE_NOT_SKILL_CORE`, `ILA_CHANGE_CORE_EDITED`, `ILA_CHANGE_NO_MARKER`: `ila::change` changes only a core this skill made. `ila::apply` writes the design property `ILA_SKILL_CORES` (flat designs): per core its name, clock driver pin, probe bit count and a CRC32 of the probe net names. Not in the record: `ILA_CHANGE_NOT_SKILL_CORE` (also for a name that is not a debug core). In the record but the probes or the clock driver differ: `ILA_CHANGE_CORE_EDITED`. No record (a design from an older skill, or a project reopened after `save_constraints` if the property is lost): `ILA_CHANGE_NO_MARKER`. Nothing is changed.
- `ILA_CHANGE_SHARED_PORT`: `ila::change -probe_types` named a net that shares a probe port with nets that would get another type. Each signal has its own port, so these are bits of one signal, or the core was built by an earlier version of the skill. Text: "net <net> shares a port with <nets>, and one port has one probe type. Each signal has its own port, so these are bits of one signal (or the core was built by an earlier version of the skill, which put several signals on one port); to give it its own type, plan again with replace. Nothing was changed. Do not plan again with replace unless the user asks: it deletes this core and its probes." AI only: tell the user the reason in words (the bits are on one probe and cannot be split), and the code only when asked.
- `ILA_CHANGE_NET_NOT_ON_CORE`: a name in `-probe_types` matches nets in the design, but the core probes none of them. Text: "'<name>' matches nets in the design, but <core> does not probe any of them. Nothing was changed." AI only, as above.
- `ILA_CHANGE_NO_PROBES_FILE`: `ila::prove_built -ltx <file>` could not read the probes file. Text: "the probes file <file> cannot be read (<error>). Write it with write_debug_probes after opt_design, then ask again. Nothing was checked." AI only, as above.
- `ILA_CHANGE_NEEDS_DATA_PROBE`: `ila::change -probe_type trigger` (every port), or per-name types that leave every port trigger only. No probe would store data, and `opt_design` would fail (IP_Flow 19-3478). Nothing is changed.
- `ILA_CHANGE_COMPARATOR_LIMIT`: probe ports times comparators over 1024 (IP_Flow 19-3478 at `opt_design`; no DRC catches it). Each signal is a probe port, so a core with more than 64 signals cannot take 16 comparators. Nothing is changed.
- `ILA_CHANGE_DFX`: `ila::change` on a design with a reconfigurable partition. Not measured, so refused. Nothing is changed.
- `ILA_CHANGE_NOT_BUILT`: `ila::prove_built` before `opt_design` built the core (no cell, or a black box). Nothing is checked.
- `ILA_HUB_CORE_LIMIT`: Versal only. One AXI Debug Hub connects at most 64 debug cores (PG361); the design already has too many for this plan.
- Static-first route (UltraScale and UltraScale+, `routes.md`): `ILA_REFUSED_FLAGGED` (partition already flagged, ask for the pre-flag checkpoint), `ILA_REFUSED_NO_BLACKBOX`, `ILA_REFUSED_STATIC_FIRST_VERSAL`, `ILA_STATIC_FIRST_NOT_CHECKED`, `ILA_STATIC_FIRST_CORE_MISSING`, `ILA_NO_APPLY`, `ILA_BAD_OPTION`.
- `ILA_PROBES_NOT_READY`, `ILA_PROBES_EXISTS`, `ILA_PROBES_NO_DIRECTORY`, `ILA_PROBES_FAILED`: `ila::write_probes <file>`. Before `opt_design` the cores are not built (Vivado 12-5829), so nothing is written. An existing file is kept unless `-force 1` is given (Vivado 12-1574). A folder that does not exist is not made (Vivado 16-19). Any other Vivado failure is quoted.
- `ILA_PLAN_TIMEOUT`: `ila::plan` ran past `-time_budget` seconds; ask for fewer or more specific names.
- `ILA_NO_PLAN`, `ILA_OVER_BUDGET`: `apply` or `next_steps` without an accepted plan in this session, or a plan over the memory budget. `ila::change` raises `ILA_OVER_BUDGET` before any set when the new depth or memory type does not fit (free tiles, plus the core's own, minus the modelled tiles of the other cores not yet built) and names the largest depth that fits.
- `ILA_NO_INPUT_CHECK`: a step needed the architecture of the open design (UltraScale, UltraScale+ or Versal) and could not read it: no design is open, or Vivado gave no part, and `ila::check_input` has not recorded it. Open the design and run `ila::check_input`. Nothing was done. With a design open the library reads the part itself, so a skipped `check_input` no longer makes a Versal design look like another family.
- `ILA_BAD_OPTION`: `ila::plan` or `ila::change` was given an option name it does not know (`-dpth` for `-depth`), or an option with no value, or `ila::change` got no core name first. The message lists the valid options. Nothing was planned or changed. (The static-first route raises the same code.)
- `ILA_NAME_IN_USE`: core name already exists. Run `ila::reset` first. (If Vivado says a name is already used by something it does not list as a debug core, `apply` takes the next free name and says so.) With `-replace_existing 1` it stops before it deletes anything when a core that stays (not a `u_ila_*` core) already holds a planned name; run `ila::plan` again, which picks a free name.
- `ILA_CREATE_FAILED`, `ILA_OPTION_REFUSED`, `ILA_CONNECT_MISMATCH`: Vivado refused a step. `ILA_CREATE_FAILED` carries Vivado's own text for any `create_debug_core` failure the library does not recognize.
- `ILA_NOTHING_INSERTED`: no net could be probed, and at least one was refused because an existing core already probes it (N20); the message says how many were N20.
- `ILA_BAD_ITEM`: a name is empty or ends with a slash, or it is written in the removed item syntax (a type word and a colon in front of the name). It could have matched the whole design, so the plan stops and nothing is planned. The name alone is enough: the library finds the register or the net itself.

## Plan lines to report

- `ALIAS`: two names for one net, both asked for. Said only when the net IS probed.
- `REJECTED`: one line per refused net. Each code prints its first 5 lines, then one count line (`REJECTED N more [N16] refused nets`), so no code is hidden behind another. N01 and N17 refuse a name the user asked for, N20 marks a net an existing debug core already probes, and N12 marks a net on an output port. All four are always printed in full. Every refused net stays in the plan and in the session facts (kept in memory, no file is written) (`rejected_<net>`). A reason already printed for the same code is not repeated (`same reason as <net>`).
- `BUS`: printed only when a bus has gaps. Gives probed bits, unprobed bits, and the declared width: the width of the net's own bus in the netlist (`declared width 32 (net bus count[31:0])`), or the width of a port pin bus (an HBM `AWADDR[36:0]`) when each probed bit sits on the pin with the same index. A pin bus of a carry or LUT cell is never used.
- `MARK_DEBUG:` line per core: how many probe nets carry MARK_DEBUG.
- `BUDGET`: printed when over budget. See `memory-budget.md`.
