Anything not proven is **UNCONFIRMED**.

**Emission primitives.** Calls are `name(k1 = v1, k2 = v2)`, with arguments joined by `", "` in insertion order. `addArg` adds a leading `'` unless the value already starts with one, and a trailing `'` unless it already ends with one (the two checks are independent); `addRawArg` emits it verbatim; booleans become `True`/`False`. Values are never escaped, so a `'` inside one breaks the script. `appendPrint(s)` writes `print("s")`, `appendComment(s)` writes `# s`, and `appendTryExcept(a, b)` writes `try:`, `\t<a>`, `except:`, `\t<b>`.

**Script skeleton, in order**
1. `#!/usr/bin/env python3`, `import vitis`, `import os`, `import shutil`, then `# This script is auto-generated by Vitis IDE` and the banner prints (`\n---...`, `  Migrating classic Vitis projects to Vitis Unified IDE`, `---...`).
2. `# Create Vitis client`, `client = vitis.create_client()`, `client.update_workspace('<new ws>')`, `print('Successfully created Vitis client on workspace {}'.format(client.get_workspace()))`.
3. Repositories. If the user platform repos (Eclipse prefs) contain a path outside the Classic workspace, the script gets `print("Setting user platform repositories...")` and `client.add_platform_repos(['p1','p2'])`. If local or global SW repos exist, it gets a `NOTE: The workspace has local and/or global software repositories...` print and a *commented* `# client.set_sw_repo(level = 'LOCAL', path = ['r1','r2'])`. Where these preferences live on disk is UNCONFIRMED.
4. `print("Migrating projects from classic Vitis IDE")`, the per-project blocks, then `vitis.dispose()`. The script is written to `<new ws>/migrate.py`.

**Project selection and order.** Only projects with dialog status 1 ("Migration is supported.") are migrated (§1). They are stable-sorted: platform projects, then all others, then system projects. Within a group the order is Eclipse `getProjects()` (UNCONFIRMED; normally alphabetical). A handler exception is only logged and the script continues, so partial lines may remain.

## 1. Detecting the project type on disk

`ProjectHandlerFactory.newHandler` tests the rows in this order. The first match wins.

| # | Handler | `.project` nature(s) | Settings file, root element |
|---|---|---|---|
| 1 | Platform | `com.xilinx.sdx.scw.platformProject` (legacy: `com.xilinx.sdk.scw.project.ScwProjectNature`) | `platform.spr` (JSON) |
| 2 | EmbeddedApp | `com.xilinx.sdx.sdk.core.SdkProjectNature` | `<proj>.prj`, `sdkproject:SdkProject` (ns `http://www.xilinx.com/sdkproject`); `isStaticLib`/`isSharedLib` not `true` |
| 3 | AcceleratedApp | `com.xilinx.ide.accel.core.hostApplicationNature` + `embdAccelHostNature` or `datacenterHostNature` | `<proj>.prj`, `AcceleratedHostProject` (ns `.../acceleration/hostApplication`); `flow` = `EMBEDDED_ACCELERATION` or `DATA_CENTER` |
| 4 | Aie | `com.xilinx.sdx.aie.core.aieproject` | `<proj>.prj`, `aieproject:AIEProject` |
| 5 | HwKernel | `com.xilinx.ide.accel.core.hwKernelNature` | `<proj>.prj`, `HwKernelProject` (ns `.../acceleration/hwkernel`) |
| 6 | System | `com.xilinx.sdx.system.systemprojectnature` + `com.xilinx.sdx.system.core.embedded` (or `.unified`/`.unifiedSoftware`) | `<proj>.sprj`, `systemproject:SystemProject` |
| - | Default | anything else: HW link (`hwLinkNature`), SDK libraries, OpenCL | blank, `# Migration for project '<p>' is not supported`, `print("Skipping project '<p>' ...")`, blank |

- **System match.** The handler matches on `isDcSystemProject || isEdgeSystemProject || embedded nature`. The DC and Edge cases come from `PlatformHelper.isSDAccel/isSDSoc(platform)` and cannot be derived from files (UNCONFIRMED), so treat any `.sprj` as a system project. HW link content is migrated by the System handler.
- **Settings files.** `.prj`/`.sprj` are EMF XMI with ecore feature names as attributes: `name location platform platformUID systemProject sysConfig runtime cpu cpuInstance os`, a child `<template appTemplateName=.../>`, and `<configuration name= id=><configBuildOptions xsi:type=...>`.
- **Excluded.** Status 2 is an SDK *standalone* app whose `platform` is outside the workspace and whose `dirname(platform)/hw/sdt` is missing ("...refers a platform outside the current workspace. Migrate the platform first..."). Status 3 is "Unknown project type".

## 2. Per project type: what is read and what is emitted

`<loc>` is the Classic project location. `P` is the platform argument: if the `.prj` `platform` path is under the workspace root it becomes `client.get_workspace() + '/<relative>'`, otherwise `'<abs>'`.

### 2.1 Platform (`PlatformProjectHandler`)

**Reading.** The model is loaded through XSCT (`platform read {<spr>}`). `BspSettingsReader` parses `platform.spr` directly, using `systems[0].domains[]` and the keys `domainName processors os compatibleApp addedLibs libOptions` (CONFIRMED). The other getters map to these sample keys (mapping UNCONFIRMED):
- name -> `platformName`; desc -> `platformDesc`; device -> `deviceType` (`zynqMP`/`versal`); domain display name -> `domainDispName`.
- handoff -> `platHandOff` (relative or absolute) or `platIntHandOff` (`<platformDir>/hw/x.xsa`); boot files generated -> `platIsNoBootBsp=="false"`.
- boot domain -> `domType=="bootDomain"` (others are `"mssDomain"`); qemu fields -> `qemuArgs`/`qemuData`/`pmuQemuArgs`.
- The keys behind the fsbl/pmufw ELF and the Linux bif/boot/image fields are UNCONFIRMED.

**Emission:**
```
# Migrating platform project : '<spr path>'
print("Creating platform component '<name>'")
platform = client.create_platform_component(name = '<name>', hw_design = '<handoff>'[, no_boot_bsp = True | , fsbl_target = 'psu_cortexr5_0'][, fsbl_path = '<fsbl>'][, pmufw_Elf = '<pmufw>'])
platform.update_desc(desc = '<desc>')                                   # only if desc non-empty
# per NON-boot domain, in file order:
print("Adding new domain '<dom>' for cpu: '<proc>' and OS: '<os>'")
print("NOTE: Converting the cpu instance '<orig>' to '<new>'")           # Versal + standalone only (§5)
domain = platform.add_domain(cpu = '<proc>', os = '<os>', name = '<dom>', display_name = '<disp>'[, support_app = '<compatibleApp>'])
print("Configuring the domain '<dom>'...")
domain.set_qemu_data(path = <dir expr>)                                 # qemu-data (NOT copied)
shutil.copy(src = '<src>', dst = <expr>)                                # before each copied file
domain.set_qemu_args(qemu_option = 'PS', path = <file expr>)            # qemu-args
domain.set_qemu_args(qemu_option = 'PMU', path = <file expr>)           # pmuqemu-args
# Linux OS:      domain.set_bif(path = ..) [copy], domain.set_boot_dir(path = ..) [copytree], domain.set_sd_dir(path = ..) [copytree]
# standalone OS: BSP block below
platform.build()                                                        # after all domains
```
- `no_boot_bsp = True` is added when boot files are not generated. Otherwise, on ZYNQ_MP, `fsbl_target` is added when the first boot domain whose name contains `fsbl` has `processors` equal (case-insensitive) to `psu_cortexr5_0`. `pmufw_Elf` is spelled exactly so in both 2024.2 and 2026.2.
- `os` becomes `freertos` if it starts with `freertos`. `support_app` is added only if `compatibleApp` contains `fsbl`. Empty fields are skipped; field order follows the SCW field container (UNCONFIRMED).

**BSP block (standalone/FreeRTOS).** It starts with `print("Migrating BSP settings for the domain '<dom>'")`. Each `addedLibs` entry (name before `:`, e.g. `xilffs:5.3`) produces:
```
# Adding library xilffs
try:
	if not any('xilffs' == lib['name'] for lib in domain.get_libs()):
		domain.set_lib(lib_name = 'xilffs')
except:
	print('ERROR: Failed to add library - xilffs')
```
`libOptions` entries are classified below. Only JSON-object entries and their primitive values are read, so `libOptionNames` and `libsContainingOptions` are skipped. Each call is wrapped in try/except with `print('ERROR: Failed to set config param <param> for ...')`.

| `libOptions` key | Comment | Call |
|---|---|---|
| == domain `processors` | `# Setting config params for processor` | `domain.set_config(option = 'proc', param = 'proc_<k>', value = '<v>')` |
| == domain `os` | `# Setting config params for OS <os>` | `domain.set_config(option = 'os', param = '<os>_<k>', value = '<v>')` |
| other (library) | `# Setting config params for library <lib>` | `domain.set_config(option = 'lib', lib_name = '<lib>', param = '<LIB upper>_<k>', value = '<v>')` |

### 2.2 Embedded app (`EmbeddedAppProjectHandler`)

Reads the `.prj` attributes `name platform cpu cpuInstance os`, `template/@appTemplateName`, the `.project` nature `org.eclipse.cdt.core.ccnature`, and `.cproject`.
```
# Migrating application project : '<proj>'
print("Creating application component '<name>'")
app = client.create_app_component(name = '<name>', platform = P, domain = '<cpu>', template = '<T>')
shutil.copytree(src = '<loc>/src', dst = app.component_location + '/src', dirs_exist_ok = True)
app.set_app_config(...)            # per .cproject option with a value or defaultValue (§3)
```
- `domain` is the `.prj` `cpu` attribute, i.e. the *domain name* (e.g. `standalone_domain`), not `cpuInstance`.
- `T` is `linux_empty_application` if `os` equals `Linux` (case-insensitive), else `empty_application`. The original `appTemplateName` is kept only if it contains `fsbl`, or if `getSimplifiedVersalProc(cpuInstance)` is one of `psu_pmu_0 psu_psm_0 psv_pmc_0 psv_psm_0 psx_pmc_0 psx_psm_0`. Unified rejects such an app on a user
  domain (`Invalid Template 'zynqmp_fsbl' selected for Domain ...`), so `classic2unified.py` reports these boot-firmware
  apps as not migrated instead; Unified builds the FSBL/PMUFW/PLM in the platform's boot domain.

**Option selection.** Only the default config is read (`IManagedBuildInfo.getConfigurationName()`; its on-disk source is UNCONFIRMED). A C++ project (with `ccnature`) reads only `natureFilter="ccnature"` tools, otherwise only `cnature` tools; `both` tools (assemblers) are skipped. Options match by base id (`option/@superClass`). An option with no `value=` takes its `defaultValue=` (for example the Release optimization level `-O2`); an option with neither is left at the plugin default and skipped. Lists are compared as sets.

**Option values by type.** A boolean gives `[command]` if true, else `[]`. An enumerated option gives `[enum command]` (§3). A string gives `[value]`; for `*.compiler.misc.other` and `*.c.link.option.ldflags` the value is split on whitespace, `-c` and `-specs=*` are dropped, and the rest is rejoined with `' '`. A list (`listOptionValue/@value`) is used as-is. Every value then passes through the §4 variable rewrite.

**Output (exact spacing)**
- Empty: `app.set_app_config(key='K', values='')`.
- K in {`USER_COMPILE_OPTIMIZATION_OTHER_FLAGS`, `USER_COMPILE_DEBUG_OTHER_FLAGS`, `USER_COMPILE_OTHER_FLAGS`, `USER_LINK_OTHER_FLAGS`}: join with `' '`, wrap in `"..."` unless it is a Linux app, apply regex `$` -> `$$`, then emit `app.set_app_config(key='K', values='<s>')`.
- Otherwise: `app.set_app_config(key='K', values=['a','b'])` (items joined by `,`; literal `\$` -> `\$\$`).

### 2.6 System project and its HW link (`SystemProjectHandler`)

```
print("Creating system project '<name>'")
system_project = client.create_sys_project(name = '<name>', platform = P)   # workspace-relative P only with the embedded nature
shutil.copy(src = '<file>', dst = system_project.project_location)          # top-level files not *.prj, *.sprj, .*
```
**HW link (accelerated).** Accelerated projects are not migrated by this skill; they are reported as not supported.

**Package / Linux image for accelerated hosts.** Accelerated projects are not migrated by this skill; they are reported as not supported.

**Applications** (`applications/@name` of the active config). Missing or closed projects, HwKernel, and HwLink are skipped.
Accelerated host and AIE apps are not migrated. An embedded SDK app gives `system_project.add_component(name = '<n>')`.

## 3. `.cproject` option id -> `set_app_config` key (embedded app)

Each suffix exists with both the `xilinx.gnu.` and the `xilinx.armcc.` prefix and maps to the same key. Ids not listed (e.g. `*.inferred.swplatform.*`) are ignored.

| Option id suffix | Key | Option id suffix | Key |
|---|---|---|---|
| `compiler.symbols.defined` | USER_COMPILE_DEFINITIONS | `compiler.misc.verbose` | USER_COMPILE_VERBOSE |
| `compiler.symbols.undefined` | USER_UNDEFINED_SYMBOLS where the install lists it (later builds); otherwise `-U<symbol>` in USER_COMPILE_OTHER_FLAGS (2026.2: the listed USER_UNDEFINE_SYMBOLS is ignored) | `compiler.misc.ansi` | USER_COMPILE_ANSI |
| `compiler.dircategory.includes` | USER_INCLUDE_DIRECTORIES | `compiler.misc.other` | USER_COMPILE_OTHER_FLAGS |
| `compiler.option.warnings.allwarn` | USER_COMPILE_WARNINGS_ALL | `c.link.option.nostart` | USER_LINK_NO_START_FILES |
| `compiler.option.warnings.toerrors` | USER_COMPILE_WARNINGS_AS_ERRORS | `c.link.option.nodeflibs` | USER_LINK_NO_DEFAULT_LIBS |
| `compiler.option.warnings.syntax` | USER_COMPILE_WARNINGS_CHECK_SYNTAX_ONLY | `c.link.option.nostdlibs` | USER_LINK_NO_STDLIB |
| `compiler.option.warnings.pedantic` | USER_COMPILE_WARNINGS_PEDANTIC | `c.link.option.strip` | USER_LINK_OMIT_ALL_SYMBOL_INFO |
| `compiler.option.warnings.pedantic.error` | USER_COMPILE_WARNINGS_PEDANTIC_AS_ERRORS | `c.link.option.libs` | USER_LINK_LIBRARIES |
| `compiler.option.warnings.nowarn` | USER_COMPILE_WARNINGS_INHIBIT_ALL | `c.link.option.paths` | USER_LINK_DIRECTORIES |
| `compiler.option.optimization.level` | USER_COMPILE_OPTIMIZATION_LEVEL | `c.linker.option.lscript` | USER_LINKER_SCRIPT |
| `compiler.option.optimization.flags` | USER_COMPILE_OPTIMIZATION_OTHER_FLAGS | `c.link.option.ldflags` | USER_LINK_OTHER_FLAGS |
| `compiler.option.debugging.level` | USER_COMPILE_DEBUG_LEVEL | `compiler.option.debugging.other` | USER_COMPILE_DEBUG_OTHER_FLAGS |

Enum commands from `com.xilinx.sdk.managedbuilder` `plugin.xml`:
- Optimization: `gnu.c.optimization.level.{none,optimize,more,most,size}` -> `-O0 -O1 -O2 -O3 -Os`.
- Debug: `gnu.c.debugging.level.{none,minimal,default,max}` -> (none) `-g1 -g -g3`, with `isDefault` = `default`.
- Defaults: `misc.other` = `-c -fmessage-length=0 -MT"$@"`, `warnings.allwarn` = `true`, `misc.verbose` = `false`. Whether CDT treats a missing enumerated `defaultValue` as the `isDefault` value is UNCONFIRMED.

## 4. Path rewriting rules

| Where | Input | Output |
|---|---|---|
| `.cproject` values (§2.2) | starts with `${workspace_loc:${ProjName}` (§2.2 also accepts a leading `"`) | regex `\$\{workspace_loc:\$\{ProjName\}\/(.*)\}` -> `${CMAKE_SOURCE_DIR}/$1`; other `workspace_loc` forms unchanged |
| same | starts with `${env_var:` (§2.2 also `"${env_var:`) | `${env_var:` -> `$ENV{` |
| `platform` argument | absolute path under the workspace root | `client.get_workspace() + '/<rel>'`; otherwise verbatim. AIE is always verbatim |
| platform resources | starts with `<platformDir>`; `R` = value minus `<platformDir>/resources/<plat>` | dst `platform.project_location + '/resources/R'` (`R` starts with `/`, giving `//`); src `'<platLoc>/resources/<plat>R'`; files use `shutil.copy`, dirs use `shutil.copytree(..., dirs_exist_ok = True)` |
| same | does not start with `<platformDir>` | `'<value>'`, no copy |

`qemuArgs` is `<platformDir>/resources/<plat>/<domain>/qemu_args.txt`, which is `<platform project>/resources/<plat>/<domain>/qemu_args.txt` on disk.

## 5. CPU-name conversion

- **`Utils.getSimplifiedVersalProc(p)`** returns the first of `psv_cortexa72`, `psv_cortexa72_0`, `psv_cortexa72_1`, `psu_cortexr5`, `psu_cortexr5_0`, `psu_cortexr5_1`, `psv_pmc_0`, `psv_psm_0` that `p` ends with; otherwise `p` unchanged. Example: `versal_cips_0_pspmc_0_psv_cortexa72_0` -> `psv_cortexa72_0`. Note the R5 entries are `psu_` (ZynqMP naming), so Classic leaves
  `versal_cips_0_pspmc_0_psv_cortexr5_0` as is, which Unified rejects (`Invalid Processor name`). `classic2unified.py` converts the R5 cores too
  (`psv_cortexr5`, `psv_cortexr5_0`, `psv_cortexr5_1`).
- **Platform `add_domain`.** Applied only for VERSAL devices with a standalone OS (`IScwStandaloneOs`; whether FreeRTOS counts is UNCONFIRMED). The `NOTE: Converting the cpu instance` print is emitted even when nothing changes.
- **Embedded app.** Applied to `cpuInstance` only to choose the template (§2.2); not emitted.
- **Other rules.** ZynqMP `fsbl_target` is only ever `'psu_cortexr5_0'` (§2.1). OS names starting with `freertos` become `freertos`.

## 6. Known exporter limitations and warnings

- **Printed or commented strings:** "Migration for project '%s' is not supported" / "Skipping project '%s' ..."; "Warning: Cannot migrate user managed kernel to the container"; the package-options WARNING; the host-app -D/-I/-l/-L NOTE; the SW-repo NOTE; "Failed to create HLS component configuration ... configured manually"; "... does not have any managed kernels".
- **Dialog and tutorial:** the dialog warns "The workspace has local and/or global software repositories. Migrate the software repositories first...". The tutorial adds that external repos and BSP source edits are not migrated.
- **Scope:** one build config only (default or active). Boot domains (FSBL, PMUFW) are never added; Unified regenerates them. Libraries are skipped. Apps become empty templates plus a copy of `src/`.
- **Copying gaps:** `qemu-data` dirs are referenced but **not copied** (copy=false), and `copyPlatformResources()` is never called. The AIE `data/` copytree is unconditional and fails if `data/` is missing. Package options are ignored unless rootfs or kernel image is set.
- **Exporter-only steps:** the exporter's HW kernel and HW link migration used the Classic makefile generators and ran v++ at
  export time. `classic2unified.py` does not migrate accelerated projects; it reports them as not supported.
- **Failures:** a platform read failure skips the project ("Failed to read platform project '%s'. Skipping..."). Errors go only to the Eclipse log.
- **2026.2 API check** (`cli/vitis/*.py`): every emitted method exists except `client.set_sw_repo`, which is only emitted as a comment.
